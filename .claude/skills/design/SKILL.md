# 화면 디자인 규칙 (이 프로젝트에서 사용자와 합의한 것)

사용자는 한국어로 대화한다. 화면 글은 모두 한국어. 아래는 이미 합의된 규칙이므로 새 화면도 같은 기준을 따른다. 새로운 결정이 생기면 이 파일과 `docs/design.md`에 함께 기록한다.

## 0. 작업 순서 (가장 중요)
1. **새 화면은 목업을 먼저 보여 주고 사용자와 정한 뒤 구현한다.** 목업은 정적 HTML을 만들어 브라우저로 스크린샷을 찍고 `SendUserFile`로 보낸다.
2. **목업도 앱의 실제 색·모양을 그대로 쓴다.** 임의의 색(예: 파란색)을 쓰지 않는다. 실수한 적이 있다: 목업을 손으로 만들면서 파란색을 썼더니 사용자가 앱은 초록이라고 지적했다.
3. 구현 후에는 실제 브라우저(Playwright + Edge)로 확인하고 스크린샷을 보낸다. 검증용으로 만든 개발 DB 데이터는 확인 후 지운다.
4. 커밋은 사용자가 요청할 때만, **API와 화면을 따로**, 작은 단위로. 공유 문서는 단계별로 나눠 커밋한다.

## 1. 색과 테마
- 강조색은 **초록**(`--primary: oklch(0.58 0.19 135)`, 다크는 `oklch(0.76 0.2 135)`). 색은 `frontend/src/index.css`의 CSS 변수/Tailwind 토큰(`bg-primary`, `text-primary`, `bg-accent`, `text-muted-foreground` …)만 쓴다. 색 값을 직접 쓰지 않는다.
- 라이트/다크 모두 동작해야 한다. 경고 칩 같은 예외 색은 `dark:` 변형을 함께 둔다.
- 부정 동작(반려·비활성화·삭제)은 `variant="destructive"`, 주 동작은 기본(초록), 보조는 `outline`.

## 2. 구성 요소는 shadcn/ui(Base UI) 것을 쓴다
`frontend/src/components/ui/`: Button, Input, Label, Dialog, Select, DropdownMenu(CheckboxItem 포함), Table, Tabs, Badge, Card, Sonner(toast) 등. 새 컴포넌트가 필요하면 먼저 이것들로 조합할 수 있는지 본다.
- Dialog 폭은 `sm:max-w-2xl` / `sm:max-w-3xl`처럼 **`sm:` 접두사**를 붙여야 적용된다.
- 체크박스는 `<input type="checkbox" className="size-4 accent-primary">`.
- 알림은 `toast`(sonner): 성공 `toast.success`, 실패 `toast.error`, 일부만 처리됨 `toast.warning`.

## 3. 화면 골격
- 상단 메뉴(상위) → 좌측 메뉴(중메뉴 → 소메뉴) → 우측 화면. 메뉴 구조는 **서버(DB `menus`)가 내 권한으로 볼 수 있는 것만** 내려준다(`/api/menus/mine`). 권한이 없는 메뉴는 **아예 보이지 않아 클릭할 수 없고**, 주소로 직접 열면 "접근할 수 없는 페이지입니다"를 보여 준다.
- 화면의 버튼·영역 표시는 `useCan('권한코드')`로 한다. `role === 'admin'` 같은 비교를 쓰지 않는다. (실제 차단은 서버가 같은 권한표로 하며, 화면 숨김만으로 끝내지 않는다.)
- 권한 이름·선택지는 고정 목록이 아니라 `useRoles()`(DB `roles`)에서 받는다. 상태·판정 값은 DB의 영문 코드이고 한글은 화면에서 매핑한다.
- 페이지 제목은 `text-xl font-semibold` + 한 줄 설명(`text-sm text-muted-foreground`).

## 4. 목록(게시판) 화면
- **조회 줄**: 상태 칩(건수 표시, 하나만 선택) + 콤보박스 필터(권한 등) + 검색 입력. 조건이 바뀌면 1쪽으로, 선택은 비운다.
- **상태별로 열이 달라진다**(예: 승인 대기 → 신청 권한·신청일, 만료 → 만료일·해제 요청). 한 화면에서 상태 필터로 구분하며 화면을 따로 만들지 않는다.
- **페이징은 항상 공통 `Pagination` 컴포넌트**: 좌측 = `총 N건` + 페이지 크기 콤보(20/50/100/1000개씩, 기본 20), **가운데 = 번호 이동**(현재 페이지가 속한 10개 묶음, « ‹ › »), 우측 = `현재 / 전체 쪽`. 새 목록도 이것만 쓴다(`lib/paging.ts`, 서버 `src/paging.mjs`).
- 목록 행의 편집 진입 버튼 이름은 **"수정"**("상세"가 아님).
- 빈 목록·불러오는 중·오류 문구를 표 안에 한 줄로 보여 준다.

## 5. 일괄 처리
- 체크박스로 고르면 목록 위에 **처리 바**가 나온다(`bg-accent`, 초록 테두리): `N명 선택 | [주 동작] [권한 지정 ▾] [부정 동작]`.
- 헤더 체크박스는 **현재 페이지만** 선택. 페이지가 더 있으면 "조건에 맞는 전체 N명 선택" 링크를 보여 주고, 처리할 때 서버 상한(100명)에 맞춰 **자동으로 끊어** 순서대로 호출한 뒤 결과를 합친다.
- 대상이 아닌 항목은 건너뛰고 **사유를 알려 준다**("N명 처리했습니다 (건너뜀 M명)"). 되돌리기 어려운 처리(반려·비활성화)와 100명 초과는 `confirm`으로 한 번 확인한다.
- 전체 보기처럼 상태가 섞인 화면에서는 일괄 처리를 숨긴다.

## 6. 모달(수정/상세)
- 넓게(`sm:max-w-3xl`) 구역으로 나눈다: **계정 / 소속·연락처 / 변경 이력** 같은 소제목(`text-xs font-semibold text-primary`, 아래 얇은 선).
- 하단: 좌측에 부정 동작, 우측에 `닫기`와 주 동작. 모달이 휑하지 않게 관련 정보(이력 포함)를 함께 둔다.
- 임시 비밀번호처럼 한 번만 보여 줄 값은 모달 안에 강조 상자로 보여 주고 복사 버튼을 둔다(닫으면 다시 못 본다고 안내).
- 모든 변경은 서버가 이력(`*_history`)에 남기고, 모달이나 화면 하단에 "변경 이력"으로 보여 준다.

## 7. 표(체크 표 등)
- 항목이 많아 가로로 넘칠 수 있는 표는 `overflow-x-auto` + **첫 열 고정**(`sticky left-0 bg-card`)으로 한다.
- 열이 늘어날 수 있는 표(권한 열 등)에는 **다중 선택 필터**(체크박스 달린 콤보박스, 아무것도 안 고르면 전체)를 둔다. 숨긴 열의 변경도 저장에 포함된다.
- 편집 표는 하단에 고정(sticky) 바를 두고 `변경 N건` 칩 + 변경 요약 + `되돌리기` + `저장`을 보여 준다.

## 7-2. 신규/수정, 삭제, 툴팁
- 신규와 수정은 **한 모달**로 합친다(신규 전용 항목은 신규에서만 입력, 수정에서는 읽기 전용). 수정에는 사용 현황·변경 이력을 함께 둔다.
- **삭제는 연쇄 삭제(cascade)를 쓰지 않는다.** 기본은 「사용 안 함」(선택지에서만 빠지고 기존 데이터는 유지), 진짜 삭제는 쓰는 곳·이력이 없을 때만.
- 설명 툴팁은 `<TooltipContent light>`(옅은 배경+테두리)를 쓴다. 짙은 기본 말풍선은 표를 가린다. 설명이 있는 항목만 점선 밑줄로 표시.
- 페이지 제목 줄의 주 버튼(＋ 새 …)은 제목 옆 위쪽 정렬, 아래 조회 줄과 `mb-5` 간격을 둔다.

## 8. 문구와 값
- 날짜는 `fmtDate`/`fmtDateTime`(보는 사람의 현지 시각). 건수·점수는 `tabular-nums`.
- 상태 뱃지: 사용 중은 기본(초록), 그 외(승인 대기·만료·비활성)는 `secondary`/`outline`.
- 목업이든 실제 화면이든 회사 데이터는 쓰지 않는다. 예시 이름·업체는 지어낸 것만(예: 한빛테크, 최연구).
