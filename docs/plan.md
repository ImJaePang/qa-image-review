# AI 생성 이미지 QA 검수 시스템 - 미니 프로젝트 기획서

> 목적: 입사 예정 회사(AI 이미지 라벨링/검수)의 업무 흐름을 미리 경험하기 위한 개인 연습 프로젝트
> 스택: React + Node.js + PostgreSQL + Docker (파이썬은 모델 실행부에만 사용)

---

## 1. 배경과 업무 구조

회사는 원천 데이터(사진)를 바탕으로 AI로 이미지를 생성하고, 이를 검수해서 고객(군수업체 등)에게 넘긴다.
AI 생성 이미지가 실제 모습과 괴리가 있으면 안 되는데, 수천 장을 사람이 전부 보기 어렵다.
그래서 **QA팀에 넘기기 전에 AI가 먼저 문제 부분을 찾아 분류**하는 단계가 필요하다.

```
원본 이미지 → AI 생성 이미지 → [사전 검증 AI] → 분류 → QA팀 화면에서 검수(승인/반려)
                                    ↑                    ↑
                             AI/ML팀 영역           웹 개발자(나) 영역
```

### 역할 분리
- **모델(엔진)**: 이미지 → 이상 영역 히트맵 + 박스 + 점수 (숫자만 출력)
- **검증 규칙**: 모델 출력을 보고 정상/의심/불량 판정 + 사유 부여 (설정으로 변경 가능)
- **웹/배치(내 몫)**: 배치 실행, 결과 저장, 검수 화면 제공

---

## 2. 핵심 개념 정리

| 용어 | 설명 |
|---|---|
| 라벨링/어노테이션 | 이미지에 정답 표시를 다는 작업 |
| 바운딩 박스 | 물체/영역을 감싼 사각형 `{x, y, width, height}` |
| 히트맵 | 이미지와 같은 크기의 반투명 레이어. 픽셀별 "이상할 확률" |
| 세그멘테이션 | 사각형 대신 윤곽선으로 영역 표시 |
| 신뢰도 점수 | 모델이 얼마나 확신하는지 (0~1) |
| 임계값(threshold) | 점수를 몇 이상/이하로 자를지 기준 |
| 검수(QA) | 사람이 최종 확인하는 단계 |

히트맵 → 임계값으로 자르기 → 덩어리마다 박스 + 점수 로 이어진다. 박스는 히트맵의 요약본.

---

## 3. 변환(webp) 관련 결론

- **검증(판정)은 원본 기준이 안전**: 손실 압축은 미세한 질감/노이즈를 바꿔서 판정 결과가 달라질 수 있음
- **화면 표시용 미리보기/썸네일만 별도 생성**하는 구조가 흔하고 좋음
- 원본은 그대로 보관, 화면용 사본만 생성
- 무손실 webp는 원본이 PNG일 때 용량 절감 선택지가 될 수 있음 (샘플로 실측 필요)
- 팀 사정(모델이 이미 webp로 학습 등)은 확인 필요

## 4. 모델 vs 검증 규칙

### 검증 규칙 예시 (실제 회사 기준은 다를 수 있음)
- 점수 0.9 이상 = 정상 / 0.5~0.9 = 의심 / 0.5 미만 = 불량
- 필수 부품/객체 누락 → 의심
- 박스가 이미지 가장자리에서 잘림 → 의심
- 박스 과도한 겹침 → 의심

### 사유 코드 (왜 낮은 점수인지)
- `COMPOSITE_EDGE` 합성 경계 이상
- `SHAPE_DISTORTION` 형태/구조 왜곡
- `LIGHTING_MISMATCH` 조명·음영 불일치
- `TEXTURE_ANOMALY` 질감 이상 (반복 패턴, 번짐)
- `SCALE_ANOMALY` 비율/스케일 이상
- `PART_COUNT_MISMATCH` 부품 개수 불일치 (군사 장비는 구조/개수가 정확도)

### 설명 가능성 수준
1. 사유 코드 방식 (쉬움, 웹/백엔드에서 구현 가능) ← **이번에 구현**
2. 히트맵 방식 (Grad-CAM 등, 모델 쪽 지원 필요, 웹은 오버레이 표시) ← **이번에 구현**
3. 멀티모달 LLM 설명 (의심 건 열었을 때만 보조로) ← 선택

## 5. 데이터 계약 (JSON 스키마) - 모델이 바뀌어도 화면은 안 바뀌게

```json
{
  "imageId": "img_0001",
  "fileName": "tank_0001.png",
  "width": 1920,
  "height": 1080,
  "modelVersion": "mock-v1",
  "overallScore": 0.42,
  "heatmapUrl": "/heatmaps/img_0001.png",
  "boxes": [
    {
      "x": 340,
      "y": 220,
      "width": 180,
      "height": 120,
      "score": 0.31,
      "reasonCode": "LIGHTING_MISMATCH"
    }
  ]
}
```

원칙:
- 박스 좌표는 **원본 이미지 픽셀 기준**으로 저장 (화면에서 비율 변환)
- `modelVersion`을 항상 기록 (재판정/비교용)
- 모델 호출부는 **어댑터로 분리** (오픈모델 → 자체모델 교체 대비)
- 모델 출력 테이블과 판정 규칙/결과 테이블을 분리

---

## 6. DB 설계 초안 (PostgreSQL)

- `images`: id, file_name, width, height, original_path, preview_path
- `model_runs`: id, image_id, model_version, overall_score, heatmap_path, created_at
- `detections`: id, run_id, x, y, width, height, score, reason_code
- `rules`: id, name, params(jsonb), enabled  (임계값 등 설정)
- `verdicts`: id, run_id, result(정상/의심/불량), reasons(jsonb), rule_version
- `reviews`: id, image_id, status(승인/반려/미검토), reviewer, comment, reviewed_at

## 7. 연습용 데이터 만들기

원천 데이터가 없어도 가능. **회사 자료는 절대 사용하지 않는다** (군수 관련 보안). 직접 만든/공개 이미지만 사용.

1. **ComfyUI로 정상 이미지 약 70장**: SDXL/FLUX 계열, 프롬프트 예) `main battle tank, field`, `self-propelled howitzer, field`
   - 북한군 장비는 모델이 덜 알아서 편차 큼. 일반 프롬프트부터 시작
2. **인페인팅으로 결함 약 30장**: 일부 영역을 마스크로 다시 그리기 / 다른 이미지 대충 붙이기 / 밝기 어긋나게
   - **마스크 좌표 = 정답 박스** (JSON으로 저장)
3. 정상:결함 = 약 7:3
4. 생성물은 로컬 연습용. 외부 공유 시 AI 생성물 표시 (실제 사진으로 오해 방지)

## 8. 진행 단계 (체크리스트)

### 1단계: 데이터 준비
- [ ] ComfyUI로 정상 이미지 생성
- [ ] 인페인팅으로 결함 이미지 생성 + 마스크 좌표 JSON 저장
- [ ] 위 JSON 스키마에 맞춰 "가짜 모델 결과" 파일 생성 (마스크를 블러 처리해 가짜 히트맵)

### 2단계: 백엔드 (Node.js + PostgreSQL, Docker Compose)
- [ ] docker-compose로 Postgres + Node 구동
- [ ] JSON → DB 적재 스크립트
- [ ] 목록/상세 API (분류 필터, 점수 정렬, 페이지네이션)
- [ ] 검증 규칙 층 (임계값 설정으로 판정 + 사유 부여)
- [ ] 미리보기(썸네일/webp) 생성 (`sharp`), 원본은 보존

### 3단계: React 검수 화면
- [ ] 분류 탭 (정상/의심/불량), 점수순 정렬
- [ ] 이미지 위 박스 오버레이 + 히트맵 레이어 토글 (히트맵/박스/둘 다/끄기, 투명도 슬라이더)
- [ ] 사유 뱃지 표시
- [ ] 승인/반려 + **키보드 단축키** (수천 장 검수 대비)
- [ ] 큰 이미지 대응: 썸네일 먼저 → 원본 지연 로딩, 가상 스크롤/페이지네이션
- [ ] 상태관리: Zustand, 서버 데이터: TanStack Query

### 4단계: 진짜 모델 교체 (선택)
- [ ] YOLO로 박스/점수 생성 (파이프라인 연습)
- [ ] anomalib(PatchCore)로 진짜 히트맵 생성 (정상 이미지만 학습, 한 소재에 집중)
- [ ] 모델 어댑터만 교체하고 화면은 그대로 동작하는지 확인
- [ ] (선택) 의심 건 열 때 멀티모달 LLM 보조 설명

## 9. 학습 순서 (강의)

현재 추가 구매는 불필요. 블프까지 대기.

1. **한입 리액트 실전 라이브러리 키트** (Zustand, TanStack Query, Tailwind) - 3단계에서 바로 사용
2. **Node.js 교과서** - 필요한 장만 (Express, 파일/스트림, DB 연결)
3. 파이썬 기초 - 모델 실행부 코드 읽고 고치는 수준만 (필요 시 짧게)
4. **블프 구매 후보**: Docker 강의 (입사 후 팀 상황 보고 결정해도 됨)
5. 보류: 김영한 실전 DB(Postgres 확정 후), 클로드 코드 마스터(입사 후 필요 시)
6. 건너뛰기: 실무 FE 입문 React, 바닐라 JS SPA, ES6 고급, Java 한바퀴, Excel, Figma, 스프링 입문(백엔드 확정 후), Linux(필요 시 부분만)

## 10. 입사 후 확인할 질문

1. 사전 검증 모델은 누가 만들고, **어떤 형태로 전달**되나? (파이썬 코드 / ONNX / API 서버)
2. **배치 실행은 누가 맡나?** GPU 서버 환경은?
3. 모델 출력 형식은? (박스/점수 외 필드, 히트맵 제공 여부)
4. 검증 기준(임계값, 규칙)은 누가 정하고 어디에 저장되나? (코드/설정/DB)
5. 오픈모델 → 자체모델 전환 시기와 출력 형식 변경 여부
6. 원본 이미지 포맷(PNG/JPG), 규모(장수, TB), 해상도/EXIF 유지 필요 여부
7. 변환(webp) 검토: 검증은 원본 기준인지, 미리보기용만 변환하는지
8. 기술 스택 확정 여부 (React / PostgreSQL / Docker / Node.js 추정)
9. 도메인 기준: 군사 장비 부품 개수·구조 등 "괴리" 판단 기준은 누가 갖고 있나?

## 11. 주의사항

- 회사 데이터/자료는 개인 연습에 절대 사용 금지 (군수 관련 보안)
- 모델 호출부는 어댑터로 분리, 출력 형식 고정
- 판정 임계값은 코드 하드코딩 금지, 설정/DB로 관리
- 어떤 모델 버전으로 판정했는지 항상 기록
- 이 문서의 회사 업무 구조는 대화 내용 기반 추정이므로 입사 후 확인 필요
